1. 문제: 시각적 문제를 기호 처리로 풀었다

젬대버(Gemmaton) 1세대의 근본 문제는 "이 화면에서 뭘 해야 하지?"라는 시각적 질문을 "이 상태에서 어떤 규칙이 적용되지?"라는 기호 처리 질문으로 풀었다는 것입니다. 해시 기반 상태 분류, 템플릿 매칭, OCR — 모두 규칙 기반 접근이었습니다.

젬대버2의 방향을 바꿨습니다: 비전 모델이 화면을 직접 보고 판단하게 합니다. 하지만 어떤 모델을 쓸 것인가?

Gemma E2B (로컬)Codex GPT-5.4 (클라우드)
비전 능력약함매우 강함
속도~3초/호출~25초/호출
비용무료 (로컬)API 비용
크기3.46GB클라우드
오프라인가능불가

회장님의 방침: Gemma E2B를 핵심 비전 모델로, Codex는 개발 단계에만 사용. 이 제약 안에서 최선을 찾는 게 이 POC의 목표였습니다.

  • 게임: 대항해시대 오리진 (Uncharted Waters Origin)
  • ADB: WiFi 연결 (192.168.0.105:34735)
  • 비전 서버: llama.cpp + Gemma 4 E2B (port 8080)

모든 실험은 이 항구 화면에서 시작합니다:

항구 화면 원본 (3040x1904) — Codex가 교역소(365,272), 출항소(2627,239), 미니맵(2726,490), 지구본 버튼(2948,620)을 정확히 찾음

3. 실험 1-5: Gemma E2B 단독 비전 — 전면 실패

먼저 Gemma E2B에게 아무런 힌트 없이 화면을 분석해달라고 했습니다.

실험 1: 기본 프롬프트 — "교역소, 출항소, 미니맵 위치를 찾아주세요"
결과: ❌ 일반적 설명만 반환. JSON 파싱 불가. "화면 왼쪽 하단 근처" 같은 추측만
실험 2: 상세 UI 설명 추가 — "미니맵은 우측 상단 원형, 교역소는 저울 아이콘"
결과: ❌ 동일. 이미지를 안 보고 텍스트 지식으로 추측
실험 3: 화면 분할 — 우측 상단만 크롭해서 질문
결과: ❌ 크롭해도 인식 불가
실험 4: Few-shot — Codex가 찾은 정답 좌표를 예시로 제공
결과: ❌ few-shot도 도움 안 됨. "스크린샷 내에서 해당 요소들을 찾기 어렵습니다"

해상도를 바꿔도, 프롬프트를 다르게 해도, 예시를 줘도 결과는 같았습니다. Gemma E2B는 이 게임의 UI를 인식하지 못합니다.

16단계 명암 변환 — 컬러/명암 무관하게 결과 동일
그리드 오버레이 — 좌표를 눈에 보이게 해도 읽지 못함

4. 실험 6: Codex가 쓴 프롬프트 — 7px 오차의 비밀

여기서 전환점이 왔습니다. Codex에게 "Gemma가 이 화면에서 UI를 찾으려면 어떤 추가 정보가 필요한가?"라고 물었습니다.

Codex의 답변: 화면의 각 UI 요소에 대해 시각적 특징을 상세히 묘사:
  • 교역소 버튼: "좌상단(x 3~21%, y 10~19%), 매우 밝은 큰 가로 직사각형, 중앙에 저울 아이콘과 한글 텍스트"
  • 미니맵: "우측 중앙(x 80~100%, y 14~38%), 큰 세로 직사각형, 내부에 마름모·원·앵커 심볼"
  • 지구본 버튼: "미니맵 오른쪽 아래, 두꺼운 원 테두리와 내부 십자선"

Codex가 작성한 프롬프트로 Gemma에게 다시 질문했습니다. 결과:

실험 7B: 좌표 범위 좁힘 + 상세 묘사

"trade_shop": (365, 270) → GT(365, 272) = 7px ✅✅
"trade_shortcut": (2490, 235) → GT(2466, 238) = 24px ✅✅
"departure_shortcut": (2625, 235) → GT(2627, 239) = 4px ✅✅
"minimap_center": (2735, 490) → GT(2726, 490) = 9px ✅✅
"globe_btn": (2950, 620) → GT(2948, 620) = 2px ✅✅

★ 평균 오차: 9px!

전부 25px 이내! 프롬프트에 좌표 범위를 좁혀주고 상세히 묘사하니 Gemma E2B가 정확히 찾았습니다.

하지만... 이게 정말 이미지를 본 건가? 아니면 프롬프트의 좌표 범위 중간값을 찍은 건가?

5. 실험 7: 자율 루프 첫 시도 — JSON 파싱 버그

7B 프롬프트로 자율 루프(POC #7)를 돌렸습니다. 화면 분류 → 액션 결정 → 탭 실행 사이클.

POC #7 결과:
  • ✅ 화면 분류: port(0.95), dialog(0.95), home(0.95) — 2-bit 명암에서도 정확
  • ✅ 지구본 버튼 (2925,620) GT=(2948,620) = 28px 오차
  • ❌ 지구본을 11번 탭해도 화면 변화 없음
  • ❌ JSON 파싱 버그: 중첩 JSON에서 extract_json이 잘못된 객체 추출
원인: {[^{}]+} 정규식이 중첩 JSON을 못 파싱함 → rfind('{') 방식으로 수정

6. 실험 8: 2-bit 명암 — 회장님의 직관

회장님의 제안: "픽셀당 16개 명암 흑백으로 만들어서 처리해보자"

4단계(2-bit) 명암 변환을 적용했습니다:

원본 컬러 (1002KB)

7. 실험 10: "실제로 보는가?" — 엄밀한 반증

회장님의 촉: "만족하지마, 더 완벽히 증명될 때까지 더 다양하게 생각하고 시도해줘"

7B에서 9px 오차가 나온 게 정말 이미지를 본 건지, 아니면 프롬프트의 좌표 범위에 끌린 건지 검증했습니다.

10D: 결정적 증거 — 홈 화면에 항구 prior를 줌

프롬프트: 항구 화면이라고 속이고 항구 좌표 범위 제공
이미지: 안드로이드 홈 화면 (게임 아님)
결과: 🚨 항구가 없는데도 항구 좌표를 반환!
{"trade_shop":{"x":3040,"y":200},"trade_shortcut":{"x":2380,"y":190},...}
안드로이드 홈 화면 — 게임이 아닌데 항구 좌표를 반환함 (할루시네이션)

결론: Gemma E2B는 전체 화면에서 UI 요소를 직접 찾지 못합니다. 프롬프트 prior에 종속됩니다. 하지만 화면 분류(port/dialog/home)는 정확히 합니다. 비전이 아예 없는 게 아니라 약한 것입니다.

8. 실험 11-12: CV + Gemma 하이브리드 — 돌파구

회장님의 지적: "Gemma가 비전 능력이 없는 것은 잘못된 결론. 있는데 약하다. 그것을 보완할 방법을 찾는 게 너의 임무"

접근을 바꿨습니다. Gemma에게 전체 화면을 분석시키지 말고, 작은 조각만 분류시킵니다.

핵심 아이디어: CV로 후보 추출 → Gemma로 분류

전체 화면 (3040x1904) ↓ 전통 CV: 밝은 영역 blob 추출 (~1ms) ↓ 20개 후보 blob ↓ Gemma: 각 blob 크롭 분류 (~3s/개) ↓ 결과 매칭

Step 1: 전통 CV로 밝은 UI 영역 추출

이진화 → 연결 요소 분석 → blob 중심 좌표 추출:

CV로 추출한 밝은 UI 영역에 번호 마킹 — 20개 후보 감지

추출된 blob 목록:

# 0: ( 364, 272) 536x128 ← 교역소! # 1: (2078, 718) 420x140 # 2: (2726, 242) 572x92 ← 숏컷 영역 # 3: (2958, 608) 156x184 ← 지구본! ...

Blob #0 (364,272) vs Ground Truth (365,272) = 1px 오차! CV만으로도 교역소 위치를 정확히 찾습니다.

Step 2: 각 blob 크롭을 Gemma에게 분류

각 blob 영역을 잘라내서 Gemma에게 보냅니다:

Blob #0 크롭 → Gemma: "trade_shop" ✅
Blob #3 크롭 → Gemma: "globe" ✅
Blob #2 크롭 → Gemma: "지도" (부분 성공)

핵심 증명

증거결과의미
교역소 크롭 → "trade_shop"✅Gemma가 이미지를 봄
지구본 크롭 → "globe"✅내용 인식 성공
홈 화면 → -1 반환✅거짓 양성 없음!
실시간 분류 → "home"✅실시간에도 작동
12D: 홈 화면 테스트
프롬프트: "교역소/미니맵/지구본 있으면 선택. 없으면 -1"
결과: {"trade_shop":-1,"minimap":-1,"globe":-1}
✅ 없는 요소를 -1로 정확히 반환! 거짓 양성 없음!

이것이 핵심 발견입니다:

Gemma E2B는 전체 화면 분석에는 약하지만, 작은 영역 분류에는 능하다. 전통 CV로 "어디에 뭐가 있다"를 잡고, Gemma가 "그건 뭐다"를 판단하는 하이브리드가 최적이다.

10. 결론: 3계층 하이브리드 아키텍처

모든 실험을 종합한 아키텍처:

■ 빠른 경로: CV 규칙 (~0ms) 밝기/위치/형태 기반 → "여기 버튼 있다" 해상도 높은 고정 UI에 적합 ■ 중간 경로: CV blob → Gemma 분류 (~3s) CV로 후보 추출 → 각 크롭을 Gemma가 분류 "이건 교역소인가?" → 1px 정확도 증명 ■ 느린 경로: Codex 전체 분석 (~25s) 복잡/알 수 없는 화면만 자율 탐색, 에러 복구

이 아키텍처의 장점:

  • 실시간: 빠른 경로는 0ms, 중간 경로는 3초
  • 로컬 우선: Gemma E2B는 오프라인 작동
  • 안전망: 모르는 화면은 Codex가 처리
  • 거짓 양성 없음: 없는 요소를 -1로 반환 (12D에서 증명)
